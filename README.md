# To_to_list_using_MPA
# 📝 To-Do List Backend API

A robust, secure, and scalable RESTful API for a **To-Do List Application** built with **Node.js**, **Express**, and **MongoDB**. It features JWT-based user authentication, role/owner isolation, complete CRUD operations for todos, search & filtering, and interactive API documentation powered by Swagger (OpenAPI 3.0 via YAML).

---

## 🚀 Tech Stack & Dependencies

| Technology / Library | Purpose |
|----------------------|---------|
| **Node.js** | JavaScript runtime environment |
| **Express.js** (`express`) | Minimalist web application framework for handling routing and HTTP requests |
| **MongoDB & Mongoose** (`mongoose`) | Object Data Modeling (ODM) library for MongoDB database interactions and schema validations |
| **JSON Web Token** (`jsonwebtoken`) | Generates and verifies cryptographic bearer tokens for stateless user authentication |
| **Bcryptjs** (`bcryptjs`) | Hashes user passwords with salts before saving to ensure security |
| **CORS** (`cors`) | Cross-Origin Resource Sharing middleware to enable requests from frontend clients |
| **Dotenv** (`dotenv`) | Loads environment variables from a `.env` file into `process.env` |
| **Nodemon** (`nodemon`) | Automatically monitors file changes and restarts the development server |
| **Swagger UI Express** (`swagger-ui-express`) | Serves interactive API documentation interface directly in the browser |
| **YAMLJS** (`yamljs`) | Parses the OpenAPI 3.0 specification written in `swagger.yaml` |

## 🗄️ Database Models

### 1. User Model (`users.js`)
| Field | Type | Attributes / Notes |
|-------|------|--------------------|
| `_id` | `ObjectId` | Auto-generated by MongoDB |
| `name` | `String` | Required, trimmed |
| `email` | `String` | Required, unique, lowercase, trimmed, validated format |
| `password` | `String` | Required, hashed via `bcryptjs`, hidden by default (`select: false`) |
| `createdAt` / `updatedAt` | `Date` | Automatic Mongoose timestamps |

### 2. Todo Model (`todos.js`)
| Field | Type | Attributes / Notes |
|-------|------|--------------------|
| `_id` | `ObjectId` | Auto-generated by MongoDB |
| `user` | `ObjectId` | References `User`, required, indexed (enforces user isolation) |
| `title` | `String` | Required, trimmed, max length 100 characters |
| `description` | `String` | Optional, trimmed |
| `status` | `String` | Enum: `['pending', 'in-progress', 'completed']` (default: `pending`) |
| `priority` | `String` | Enum: `['low', 'medium', 'high']` (default: `medium`) |
| `dueDate` | `Date` | Optional due date and time |
| `tags` | `[String]` | Optional array of tags/categories |
| `createdAt` / `updatedAt` | `Date` | Automatic Mongoose timestamps |

## 📡 API Endpoints

### 🔐 Authentication (`/api/auth`)
| Method | Endpoint | Access | Description | Request Body |
|---|---|---|---|---|
| `POST` | `/api/auth/signup` | Public | Register a new user | `{ "name": "...", "email": "...", "password": "..." }` |
| `POST` | `/api/auth/signin` | Public | Login and obtain JWT token | `{ "email": "...", "password": "..." }` |
| `GET` | `/api/auth/me` | Protected | Get profile of logged-in user | `Headers: Bearer <token>` |

### 📋 To-Do Management (`/api/todos`)
> *All Todo endpoints require the `Authorization: Bearer <token>` header.*

| Method | Endpoint | Access | Description |
|---|---|---|---|
| `POST` | `/api/todos` | Protected | Create a new todo item |
| `GET` | `/api/todos` | Protected | Retrieve all todos with search, filter, sort & pagination |
| `GET` | `/api/todos/:id` | Protected | Retrieve a single todo by its ID |
| `PUT` | `/api/todos/:id` | Protected | Update todo fields |
| `PATCH` | `/api/todos/:id/toggle` | Protected | Toggle todo status between `completed` and `pending` |
| `DELETE` | `/api/todos/:id` | Protected | Delete a completed todo |

#### 🔍 Supported Query Parameters for `GET /api/todos`:
- `status`: Filter by status (`pending`, `in-progress`, `completed`)
- `priority`: Filter by priority (`low`, `medium`, `high`)
- `search`: Keyword search across `title` and `description` (case-insensitive regex)
- `sortBy`: Field to sort by (e.g. `createdAt`, `dueDate`, `priority`, default: `createdAt`)
- `order`: Sort direction (`asc` or `desc`, default: `desc`)
- `page`: Page number for pagination (default: `1`)
- `limit`: Items per page (default: `10`)

Swagger UI is configured with an OpenAPI 3.0 YAML specification:

2. Open your web browser and navigate to:

3. **To test protected endpoints:**

# 📋 TaskFlow - Multi-Page Application (MPA) Frontend

A modern, fast, and responsive frontend for the To-Do List Application built as a **Multi-Page Application (MPA)** using **React 18**, **Vite**, and **Tailwind CSS**.

---

## ⚡ Tech Stack & Architecture

- **React 18**: Component-based UI for each page.
- **Vite Multi-Page Build**: Configured via `build.rollupOptions.input` with 5 distinct HTML entry points.
- **Tailwind CSS**: Modern utility-first styling with custom indigo theme and responsive design.
- **Lucide React**: Clean SVG icon system.
- **No SPA / No React Router**: True multi-page navigation using real page loads (`<a href="/signin.html">`, `window.location.href`).
- **Native Fetch**: Lightweight universal API layer using native `fetch` (no Axios).

## 🚀 Getting Started

### 1. Install Dependencies
```powershell
cd Frontend
npm install
```

### 2. Start Development Server
```powershell
npm run dev
```
Open **`http://localhost:3000/index.html`** in your browser.

> **Note on MPA Navigation**: Vite serves all HTML pages directly:
> - Dashboard: `http://localhost:3000/index.html`
> - Sign In: `http://localhost:3000/signin.html`
> - Sign Up: `http://localhost:3000/signup.html`
> - Task Detail: `http://localhost:3000/todo.html?id=<task_id>`
> - Profile: `http://localhost:3000/profile.html`

### 3. Production Build
```powershell
npm run build
```
This compiles all 5 HTML pages and assets into the `dist/` directory using Vite's Rollup multi-page bundler.
